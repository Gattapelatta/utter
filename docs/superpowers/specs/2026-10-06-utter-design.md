# Utter — спецификация v1

**Дата:** 2026-10-06
**Статус:** на ревью
**Рабочее название:** Utter (может быть изменено до релиза)

## 1. Цель и критерии успеха

Бесплатная open-source утилита для macOS и Windows: нажимаешь назначенную клавишу, говоришь — и в активное поле вставляется чистый текст. Второй режим — то же самое, но на выходе перевод на английский в деловом или разговорном стиле.

**Для кого:** люди, которые много пишут в мессенджерах, почте, рабочих инструментах; люди, которым нужно быстро писать по-английски.

**Успех v1:**
- Установка и первая успешная диктовка — меньше чем за 2 минуты (включая получение ключа Gemini).
- Отпустил клавишу → текст вставлен: ~1,5 с для 10 с речи через провайдера по умолчанию.
- Вставка срабатывает в 100% случаев из тестовой матрицы (§9.3); там, где ОС блокирует вставку, — текст гарантированно в буфере и пользователь об этом знает.
- Ощущение дорогого нативного продукта: плавные анимации 60/120 fps, ни одного зависания или падения в стресс-тесте.
- README, который продаёт продукт за 10 секунд (GIF + одна строка).

## 3. Функциональность

### 3.1 Режимы

- **Диктовка.** Речь → текст на языке речи. Опционально «чистовая обработка» (по умолчанию включена): убирает слова-паразиты («э-э», «ну», «как бы»), повторы, расставляет пунктуацию и заглавные буквы, **не меняет смысл и не перефразирует**. Выключена → вставляется сырая расшифровка Whisper.
- **Перевод.** Речь на любом языке → английский текст в выбранном стиле:
  - **Деловой** — вежливо, чётко, профессионально, без канцелярита.
  - **Разговорный** — естественно, как пишет носитель в мессенджере, без излишней формальности.
  Перевод и чистка от паразитов делаются одним запросом к LLM.
- **Абзацы в длинных текстах** (настройка, по умолчанию **выключена**): если запись длиннее 30 с, LLM-шаг (чистовая обработка или перевод) разбивает текст на абзацы по смыслу, разделитель — пустая строка (`\n\n`). Для записей короче 30 с и при выключенной чистовой обработке в режиме Диктовки не применяется.
- Голосовые команды для знаков препинания («запятая», «новая строка») **не поддерживаются** — пунктуация только автоматическая.

### 3.2 Клавиши

- Две независимые клавиши, обе переназначаемые: **Диктовка** и **Перевод**.
- Значения по умолчанию:
  - macOS: Диктовка — Right Option, Перевод — Right Command.
  - Windows: Диктовка — Right Alt, Перевод — Right Ctrl.
- Можно назначить любую одиночную клавишу, включая F13–F19, Caps Lock, правые модификаторы. Назначение клавиши, уже занятой другим режимом, запрещено (подсказка в поле).
- **Esc** во время записи — отмена (без отправки в API).
- **Отмена сочетанием (только режим «Удержание»):** если во время удержания назначенной клавиши нажата любая другая клавиша (или вторая горячая клавиша), запись отменяется молча, а сама нажатая клавиша **не доходит** до приложения, если горячая клавиша удерживалась уже ≥ 0,3 с (решения пользователя 2026-10-07: так быстрые сочетания вроде Right-⌘+C продолжают работать, а во время записи нельзя набрать спецсимвол через удерживаемый модификатор).
- **Esc** во время записи тоже не доходит до приложения.
- Нажатия, которые Utter посылает сам (⌘V, печать), помечаются и никогда не считаются нажатиями пользователя.
- В режиме «Нажатие» во время записи другие клавиши (включая вторую горячую клавишу) игнорируются, кроме Esc.

### 3.3 Режим записи (глобальная настройка)

- **Удержание** (по умолчанию): запись идёт, пока клавиша зажата; отпустил — обработка.
- **Нажатие**: первое нажатие — старт, второе нажатие той же клавиши — стоп.
- Записи короче **0,3 с** игнорируются (случайные касания).
- Максимальная длительность записи — **10 минут**; за 30 с до лимита таймер в пилюле становится янтарным, на лимите запись останавливается и обрабатывается.

### 3.4 Вывод

- Текст кладётся в буфер обмена и вставляется в активное поле имитацией Cmd+V / Ctrl+V. После вставки текст **остаётся в буфере**.
- Настройка **«Способ вставки»**: «Вставка» (по умолчанию) / «Печать» (посимвольный ввод Unicode-событиями для приложений, не принимающих вставку).
- Детали надёжности вставки — §8.1.

### 3.4a Длинные записи — обработка по ходу речи (решение пользователя 2026-10-08)

- Пока пользователь говорит, запись раз в 0,5 с проверяется на паузу: как только набралось **≥ 7 с** речи и встретилась пауза **≥ 0,3 с**, готовый кусок (до середины паузы) сразу отправляется провайдеру, а запись продолжается. Без пауз кусок режется на **15 с** в самом тихом месте последних 4 с.
- После отпускания клавиши обрабатывается только остаток (если он длиннее 9 с — делится в самом тихом месте средней трети на две половины, которые обрабатываются одновременно), затем тексты кусков склеиваются по порядку (через пробел) и вставляются **одним разом**. Цель: ожидание после отпускания ≈ как у короткой фразы, независимо от длины речи.
- Кусок, который не получил ответа (сеть, тайм-аут), → вся запись отправляется одним запросом (запасной путь). Ошибка модели внутри куска даёт для него сырую расшифровку (как и для целой записи).
- При включённых «Абзацах в длинных текстах» нарезка не используется (абзацы делятся по смыслу всего текста).
- Каждый кусок — отдельный запрос в счётчиках; в Историю попадает одна запись с полным аудио (для «Повторить»).
- Смена устройства ввода посреди записи отключает нарезку для этой записи.

### 3.5 Язык речи

- Настройка **«Основной язык речи»**: по умолчанию — язык системы; варианты: Авто, Русский, English, Українська, Deutsch, Español, Français, + остальные языки Whisper в выпадающем списке.
- Передаётся в Whisper как параметр `language` (при «Авто» — не передаётся).

### 3.6 История и счётчики

- **История:** последние 50 записей (дата, режим, итоговый текст, сырая расшифровка, статус). Копирование в один клик. Кнопка «Повторить» для записей со статусом «ошибка». Переключатель «Сохранять историю» (по умолчанию включён); выключение очищает историю. Хранится локально.
- **Аудио** каждой записи хранится во временном файле до успешной обработки. Аудио записей со статусом «ошибка» сохраняется для кнопки «Повторить» — не более 5 последних (более старые удаляются вместе с возможностью повтора). Аудио успешных записей удаляется сразу.
- **Счётчики использования за сегодня (по локальной дате):** число запросов распознавания, секунды аудио, число LLM-запросов, токены LLM (из ответа API). Для провайдера с известными бесплатными лимитами — полоски относительно этих лимитов (значения лимитов в одном конфиг-файле).

### 3.7 Прочее

- Автозапуск при входе в систему (настройка, по умолчанию включена после онбординга).
- Автообновление через GitHub Releases (проверка при старте и раз в 24 ч, установка — по подтверждению пользователя).
- Звуков нет (решение пользователя 2026-10-08: звуки старта/стопа убраны совсем, вместе с настройкой).
- Тема: **Тёмная (по умолчанию)** / Светлая / Как в системе.

## 4. UX-поверхности

### 4.1 Иконка в menu bar / системном трее

- Монохромный знак (template image на macOS). Во время записи — маленькая красная точка; во время обработки — точка пульсирует.
- Меню: статус · Режим записи (Удержание / Нажатие) · Стиль перевода (Деловой / Разговорный) · История · Настройки… · Проверить обновления · Выход.
- Приложение не показывается в Dock / на панели задач (macOS: `ActivationPolicy::Accessory`; Windows: `skip_taskbar`).

### 4.2 Пилюля записи — «Капля» из чёлки (утверждено пользователем 2026-10-08)

Эталон движения и формы — `docs/design/drop-prototype.html`; реализация обязана совпадать с ним по формам, пружинам и таймингам.

- **Окно:** прозрачная non-activating NSPanel без рамки, клики проходят насквозь, **никогда не получает фокус**, видна поверх полноэкранных приложений и на всех Spaces. Расположение — **вверху по центру экрана**, вплотную к верхнему краю: на MacBook с вырезом пилюля «вырастает» из чёлки, на экранах без выреза — выезжает из-под верхнего края по центру.
- **Форма:** чёрный (`#000`, сливается с вырезом) остров **360 × 104 pt**, скругление только снизу `0 0 40 40`. Появление — остров плавно вырастает из ширины/высоты выреза до полного размера, исчезновение — обратно (пружина без перелёта).
- **Содержимое:** белый персонаж «Капля» (форма-капля, большие чёрные глаза-овалы, мягкий белый ореол за телом) и таймер `0:07` (Manrope 600, 21 pt, tabular, `#E6E8EA`) — **парой по центру**, промежуток 44 pt, равные отступы слева/справа и сверху/снизу. Надписей режима нет. Под вырезом камеры (верхние ~32 pt) экрана нет, поэтому Капля **48 × 50 pt**, а центр пары — на **61 pt** от верха острова (вариант C, утверждён 2026-10-08; эталон-прототип рисует Каплю крупнее — размер и позиция берутся отсюда).
- **Цвет режима:** при записи слева и справа от Капли мягко расходятся дуги (не полные кольца: сверху вырез камеры), ореол дышит в такт голосу; в Диктовке кольца и ореол **белые**, в Переводе — **голубые `#4AD8EC`**.
- **Состояния Капли:**
  - **Ожидание** (пилюля видна, но записи нет): тело неподвижно, двигаются только глаза — плавно смотрит в стороны/вверх, изредка моргает.
  - **Запись:** глаза плавно закрываются, голова покачивается в ритме сглаженной громкости голоса, расходятся кольца.
  - **Обработка:** глаза открыты, тело неподвижно, взгляд вверх и в стороны («думает»).
  - **Готово:** добрая улыбка глазами «^ ^», лёгкое всплытие вверх, вокруг делает виток светящийся спутник с хвостом (перед/за телом), у макушки по очереди вспыхивают три искорки; ~2 с.
  - **Ошибка:** глаза грустно закрываются и смотрят вниз, Капля чуть «оседает», ореол тускнеет, слева от головы, в «крыле» острова, проявляются три маленькие серые тучки (из средней — две крошечные капли); над головой их нет — там вырез камеры; текст ошибки (§8.3) показывается справа вместо таймера, 2,5 с; если у ошибки есть действие, пилюля на это время принимает клики.
  - **«Скопировано»** (вставка невозможна, §8.1) — Капля как в «Готово», справа короткий текст «⌘V».
- Если идёт новая запись, пока предыдущая обрабатывается, показывается запись; количество задач в очереди — маленькой цифрой у таймера.

### 4.3 Окно настроек

Боковое меню + контент. Разделы:
1. **Основное** — режим записи, способ вставки, основной язык речи, чистовая обработка, абзацы в длинных текстах, автозапуск, тема, язык интерфейса.
2. **Клавиши** — поля захвата клавиш для Диктовки и Перевода.
3. **Перевод** — стиль по умолчанию с примером одной и той же фразы в обоих стилях.
4. **Провайдер** — выбор Gemini / Groq / OpenAI, поле ключа (маскированное), кнопка «Проверить» (тестовый запрос, статус ✓/✗), ссылка «Получить бесплатный ключ» (для Gemini — aistudio.google.com/apikey), счётчики использования.
5. **История.**
6. **О приложении** — версия, ссылки на GitHub, «Скопировать диагностику», обновления.

### 4.4 Онбординг (первый запуск)

Пошаговые экраны в окне настроек (шаги можно пройти назад):
1. Приветствие (живое демо: русская фраза «печатается» и превращается в английский перевод).
2. Доступ к микрофону (кнопка запроса + живой статус «✓ выдано»).
3. Accessibility (только macOS; кнопка открывает нужную панель Системных настроек; статус обновляется автоматически опросом раз в 1 с).
4. Провайдер и ключ (Gemini выбран, подпись «Бесплатно, вход через Google-аккаунт», ссылка на aistudio.google.com/apikey, кнопка «Проверить»).
5. Клавиша Диктовки («Нажми клавишу, которую хочешь использовать», показан дефолт).
6. Пробная запись: «Зажми клавишу и скажи что-нибудь» — результат показывается прямо в окне.

Онбординг считается пройденным после шага 6 или по кнопке «Пропустить» на шагах 5–6 (шаги 2–4 обязательны).

## 5. Визуальный дизайн

Направление — тёмный минимализм в духе x.ai: почти чёрный фон, иерархия цветом текста, смысловые акценты, мягкие pop-in анимации. Вдохновение, не клон: собственный шрифт и айдентику x.ai не используем.

### 5.2 Типографика

- **Geist** (основной) и **Geist Mono** (клавиши, счётчики, версии) — встроены в приложение (лицензия OFL). Таймер пилюли — **Manrope** 600 (OFL, встроен).
- Заголовки: weight 500, letter-spacing −1% (крупные) … 0 (мелкие), line-height 1.1–1.2.
- Основной текст: 14 px / 1.5; второстепенный — `text-secondary`.
- Цифры таймера и счётчиков — `font-variant-numeric: tabular-nums`.

### 5.3 Поверхности

- Карточки `surface` с рамкой `border` 1 px, радиус 12 px; окна — радиус 14 px (там, где ОС позволяет).
- Пилюля: сплошной `#000` остров 360 × 104, скругление снизу 40 px, без рамки и тени (§4.2).

### 5.4 Анимации

Общие правила: анимируем только `transform`, `opacity`, `filter`; никаких `transition: all`; всё прерываемое — на пружинах (Motion) или CSS-transitions, не keyframes.

| Элемент | Параметры |
|---|---|
| Пилюля — появление/уход | остров вырастает из выреза пружиной без перелёта; втягивается обратно плавно и равномерно — 0,6 с, `cubic-bezier(0.4, 0, 0.2, 1)` (Esc — 0,35 с); окно убирается только после этого |
| Капля — все движения | только критически задемпфированные пружины `k = ω², c = 2ω` (ω: веки 7, моргание 22, улыбка 7, высота 6, наклон 6, взгляд 5.5, огибающая голоса 4.5, кольца 4, ореол 4.5, цвет режима 4) — никаких мгновенных скоростей и смены жёсткости на лету; значения — по эталону |
| Дуги записи | 3 пары боковых дуг ±30°, радиус 38→82 ед. (ease-in-out), толщина 2.2, прозрачность (1−p)^1.4 × (0.35 + 0.5·голос) |
| Готово / ошибка | спутник 1,7 с + искорки (задержки 0,35/0,53/0,71 с, 0,95 с каждая) / тучки 2,6 с (задержки 0/0,22/0,44 с) — по эталону |
| Esc | остров втягивается быстрее, без эмоции |
| Кнопки | `:active` scale 0.97, 120 мс; цвет фона/текста 150 мс |
| Переключение разделов настроек | crossfade 150 мс |
| Онбординг | первое появление fade 1 с `cubic-bezier(0.22, 1, 0.36, 1)`; каскад элементов с шагом 60 мс, pop-in 420 мс `cubic-bezier(0.2, 0.9, 0.3, 1.15)` |
| Смена темы | crossfade 250 мс, без вспышки |
| Клавиша-«кэп» | translateY 2px + уменьшение тени при реальном нажатии клавиши, 80 мс |

Запись стартует в момент нажатия клавиши, **не дожидаясь анимации**.

- `prefers-reduced-motion`: Капля не качается и не двигает глазами, кольца/спутник/тучки заменяются короткой сменой прозрачности 150 мс; эмоции — только формой глаз.

### 5.5 Иконки и бренд

Иконка приложения и знак для трея создаются отдельным шагом после реализации функциональности (вне этой спецификации).

## 6. Архитектура

### 6.1 Общая схема

```
 Клавиша ─► hotkey ─► controller ─► overlay events ─► окно пилюли (React)
                         │
                         ├─► recorder (cpal → PCM → обработка → WAV 16 кГц моно)
                         │
                         └─► job queue (FIFO)
                                 │
                                 ▼
                             pipeline: transcribe ─► [cleanup | translate(style)]
                                 │            (providers: Gemini / Groq / OpenAI)
                                 ▼
                             output (буфер + вставка/печать) ─► history, usage
```

Rust-ядро владеет всей системной логикой и состоянием. Окна React отображают состояние, получаемое через события Tauri, и вызывают команды Tauri для изменения настроек. Если все окна закрыты, приложение полностью функционально.

### 6.2 Модули Rust (`src-tauri/src/`)

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `hotkey/` | Глобальный слушатель клавиатуры. `mod.rs` — платформонезависимый интерфейс: `start(bindings) -> Receiver<KeyEvent>`, `KeyEvent { key: KeyId, kind: Down/Up, other_key_during_hold: bool }`. `macos.rs` — CGEventTap (listen-only, `kCGEventKeyDown/KeyUp/FlagsChanged`), различение левых/правых модификаторов по keycode, авто-переподключение при `kCGEventTapDisabledByTimeout/ByUserInput`. `windows.rs` — `WH_KEYBOARD_LL` на отдельном потоке с message loop, колбэк только пересылает событие в канал. Режим захвата клавиши для настроек (`capture_next_key`). | ОС |
| `controller/` | Чистая машина состояний без системных вызовов. Вход: события клавиш, тики времени, результаты задач. Выход: команды (`StartRecording(mode)`, `StopAndSubmit`, `Cancel`, `ShowOverlay(state)`). Реализует удержание/нажатие, порог 0,3 с, лимит 10 мин, Esc, отмену сочетанием. Время — через инжектируемые часы. | — |
| `recorder/` | `cpal`-захват с устройства ввода по умолчанию (или выбранного), конвертация в mono f32, ресемплинг в 16 кГц (`rubato`), high-pass 80 Гц, обрезка тишины по краям (порог по RMS с запасом 150 мс), нормализация пика к −1 dBFS, кодирование WAV 16-bit (`hound`). Уровни RMS ~30 раз/с в канал для волны. Обработка смены/отключения устройства: переключение на устройство по умолчанию без потери уже записанного. | `cpal`, `rubato`, `hound` |
| `providers/` | Трейт `SpeechToText { transcribe(wav, language) }` и `TextModel { complete(system, user) }`. Одна реализация `OpenAiCompatible { base_url, api_key, stt_model, text_model }`: Groq — `https://api.groq.com/openai/v1`, OpenAI — `https://api.openai.com/v1`. Общий `reqwest::Client` (keep-alive, HTTP/2), `prewarm()` открывает соединение. Таймаут запроса — 10 с (для аудио длиннее 2 мин — 10 с + 5 с на каждую минуту), таймаут соединения — 3 с; через 4 с ожидания пилюля показывает «Жду ответа сервера…». Вторая реализация `GeminiClient` — Interactions API Google (`POST {base}/interactions`, ключ в заголовке `x-goog-api-key`, аудио передаётся inline base64, `store: false`, подсказка языка — `generation_config.transcription_config.language_codes`). Маппинг ошибок в `ProviderError { Unauthorized, RateLimited { retry_after }, Network, Timeout, BadResponse, Server }`; у Gemini неверный ключ приходит как 400 с «API key not valid» и тоже маппится в `Unauthorized`, задержка при 429 берётся из `retryDelay` в теле. | `reqwest` |
| `pipeline/` | `run(job) -> JobResult`. Диктовка: transcribe → фильтр галлюцинаций → cleanup (если включён). Перевод: transcribe → фильтр → translate(style). При ошибке LLM-шага возвращает сырую расшифровку с флагом `degraded`. Промпты — в `pipeline/prompts/*.md`, подключаются через `include_str!`. | `providers` |
| `output/` | `deliver(text, method) -> DeliveryOutcome { Pasted, Typed, CopiedOnly(reason) }`. Детали — §8.1. `macos.rs` (NSPasteboard + CGEvent), `windows.rs` (Clipboard Win32 + SendInput). | ОС |
| `jobs/` | FIFO-очередь задач обработки; задачи обрабатываются параллельно, но результаты доставляются строго в порядке создания. | `pipeline`, `output` |
| `settings/` | Типизированная структура настроек с версией схемы и миграциями, хранение в собственном serde-JSON с атомарной записью (temp + rename), значения по умолчанию в одном месте. | — |
| `secrets/` | API-ключи в Keychain / Credential Manager через `keyring`. Ключи никогда не пишутся в лог и не отдаются в UI целиком (только маска). | `keyring` |
| `history/` | Последние 50 записей в JSON-файле в app data; атомарная запись (temp + rename). | — |
| `usage/` | Счётчики за текущую локальную дату, сброс при смене даты. | — |
| `permissions/` | Проверка и запрос: микрофон, Accessibility (macOS). | ОС |
| `overlay/` | Создание и позиционирование окна пилюли на активном экране, трансляция состояния в окно. | `tauri-nspanel` (macOS) |
| `diagnostics/` | Логи (`tracing` + ротация файлов, 5 × 1 МБ), сборка «диагностики» для буфера (версия, ОС, настройки без секретов, последние 200 строк лога). | `tracing` |

### 6.3 Интерфейс (`src/`)

- Два entry-point Vite: `settings.html` (настройки + онбординг) и `overlay.html` (пилюля).
- Состояние: Zustand-store, синхронизированный с ядром через события Tauri.
- Анимации: Motion (бывш. Framer Motion) для пружин и layout-переходов; CSS-transitions для hover/press.
- i18n: собственный лёгкий словарь `ru.json` / `en.json`.

### 6.4 Плагины Tauri

`tauri-plugin-autostart`, `tauri-plugin-updater`, `tauri-plugin-single-instance`, tray API ядра Tauri; на macOS — `tauri-nspanel`, `window-vibrancy` не используется (дизайн матовый). `macOSPrivateApi: true` для прозрачных окон.

### 6.5 Модели и промпты

- Значения по умолчанию задаются в одном модуле `providers/defaults.rs`:
  - Gemini: base `https://generativelanguage.googleapis.com/v1beta`, STT `gemini-3.5-transcribe`, текст `gemini-3.5-flash`.
  - Groq: STT `whisper-large-v3-turbo`, текст `openai/gpt-oss-120b`.
  - OpenAI: STT `gpt-4o-mini-transcribe`, текст `gpt-4o-mini`.
- **Первая задача реализации провайдеров:** сверить названия моделей и лимиты с актуальной документацией Groq и OpenAI; если модель из списка выше устарела — заменить на рекомендованного провайдером преемника и обновить эту спецификацию.
- Для STT передаётся `language` (если не «Авто») и `temperature: 0`.
- Промпты: `cleanup.md`, `translate_business.md`, `translate_casual.md`. Требования ко всем: вернуть только итоговый текст без кавычек и пояснений; не отвечать на содержание текста, даже если он похож на вопрос или инструкцию; сохранять имена, числа, ссылки, эмодзи. Инструкция про абзацы добавляется в системный промпт только когда настройка включена и запись длиннее 30 с. Текст пользователя передаётся внутри разделителей `<transcript>…</transcript>`.

## 7. Поток данных: одна диктовка

1. `hotkey` → `KeyDown(dictation)`.
2. `controller` → `StartRecording(Dictation)`: `recorder` открывает поток немедленно; `overlay` показывает пилюлю; `providers.prewarm()`.
3. Уровни от `recorder` → окно пилюли (волна).
4. `KeyUp` (удержание) или повторный `KeyDown` (нажатие) → `controller` проверяет длительность ≥ 0,3 с → `StopAndSubmit`.
5. `recorder` отдаёт WAV; если RMS всей записи ниже порога тишины → «Ничего не услышал», конец.
6. `jobs` создаёт задачу, аудио сохраняется во временный файл.
7. `pipeline`: transcribe → фильтр галлюцинаций → cleanup.
8. `jobs` дожидается своей очереди доставки → `output.deliver()`.
9. Пилюля → «Вставлено»; `history` и `usage` обновляются; временный аудиофайл удаляется.

## 8. Надёжность

### 8.1 Вставка

Порядок действий `output::deliver` (метод «Вставка»):
1. Записать текст в буфер обмена; дождаться подтверждения (macOS: изменился `changeCount`; Windows: `GetClipboardSequenceNumber` изменился), до 200 мс, с повтором открытия буфера при конфликте (Windows: до 10 попыток через 10 мс).
2. Проверить фокус: если активное окно принадлежит Utter — не вставлять, исход `CopiedOnly(OwnWindow)`.
3. Windows: если активное окно принадлежит процессу с более высоким уровнем целостности (запущено от администратора) — `CopiedOnly(Elevated)`.
4. Дождаться отпускания всех физических модификаторов (до 500 мс). macOS: событию Cmd+V явно выставляются флаги только `Command` (`CGEventSetFlags`), независимо от зажатых клавиш. Windows: перед Ctrl+V отправляются key-up для всех зажатых модификаторов.
5. Отправить нажатие V по физическому коду (macOS keycode 9, Windows `VK_V` + scan code) — работает в любой раскладке.
6. Текст остаётся в буфере (решение продукта).

Метод «Печать»: Unicode-события (macOS `CGEventKeyboardSetUnicodeString` порциями по 20 символов; Windows `SendInput` с `KEYEVENTF_UNICODE`), с паузой 5 мс между порциями. Перевод строки отправляется как Shift+Enter (в мессенджерах обычный Enter отправил бы сообщение). Буфер также заполняется.

### 8.2 Стабильность

- Слушатель клавиатуры: macOS — авто-включение tap после отключения системой; Windows — колбэк хука только кладёт событие в канал (никакой логики). Watchdog: раз в 10 с сравнивается время последнего события хука с `GetLastInputInfo`; если система видела ввод с клавиатуры/мыши, а хук молчит дольше 60 с — хук пересоздаётся.
- Сон/пробуждение: после пробуждения пересоздаются слушатель клавиатуры и HTTP-клиент.
- Смена устройства ввода во время записи — продолжение на новом устройстве по умолчанию; отсутствие устройств — ошибка «Микрофон не найден».
- Отзыв разрешений во время работы — проверка перед каждой записью; при отсутствии — пилюля с действием.
- Никаких `unwrap()`/`expect()` в рабочих путях; каждая задача обработки изолирована, паника задачи → ошибка этой задачи, а не падение приложения. Глобальный panic-hook пишет в лог.
- Single instance: повторный запуск открывает окно настроек существующего экземпляра.
- Запись во время обработки разрешена; результаты доставляются в порядке записи (§6.2 `jobs`).

### 8.3 Ошибки и сообщения

| Ситуация | Поведение |
|---|---|
| Нет ключа | Запись не начинается; пилюля «Добавь API-ключ» (клик → Настройки › Провайдер) |
| Нет доступа к микрофону / Accessibility | Запись не начинается; пилюля с действием → соответствующий шаг онбординга |
| Нет сети / таймаут | «Нет соединения» · запись в Истории со статусом «ошибка» и кнопкой «Повторить» |
| 401 | «Ключ не подходит — проверь в Настройках» |
| 429 | «Лимит {провайдер} исчерпан, сбросится через N мин» (из `retry-after` / заголовков лимитов; если нет — «попробуй позже») · запись сохраняется для повтора |
| 5xx | Один автоматический повтор через 1 с, затем «Сервис {провайдер} недоступен» |
| Ошибка LLM-шага | Вставляется сырая расшифровка; пилюля «Вставлено без обработки» |
| Тишина (RMS ниже порога) | «Ничего не услышал», запрос не отправляется |
| Пустая расшифровка или совпадение с фильтром галлюцинаций | «Ничего не услышал», ничего не вставляется |
| `CopiedOnly(*)` | Пилюля «Скопировано — нажми ⌘V / Ctrl+V» |

Фильтр галлюцинаций: расшифровка отбрасывается, если после нормализации (нижний регистр, без пунктуации) целиком совпадает с одной из известных фраз (`pipeline/hallucinations.txt`: «продолжение следует», «субтитры сделал …», «спасибо за просмотр», «thank you for watching», «thanks for watching», «you», и т. п.).

### 8.4 Бюджеты производительности

| Метрика | Цель |
|---|---|
| KeyDown → первый кадр пилюли | < 50 мс |
| KeyDown → первый записанный сэмпл | < 100 мс (встроенный микрофон) |
| Отпустил → вставлено, 10 с речи, провайдер по умолчанию, cleanup включён | ≤ 1,5 с (p50) |
| Анимации пилюли | без пропущенных кадров при 60 Гц; 120 Гц на ProMotion |
| Простой | ~0% CPU, < 80 МБ RAM суммарно |
| Размер установщика | < 20 МБ |

### 9.1 Автотесты Rust

- `controller`: удержание и нажатие; порог 0,3 с; лимит 10 мин и предупреждение за 30 с; Esc; отмена сочетанием; две клавиши (в «Удержании» нажатие второй горячей клавиши отменяет запись, в «Нажатии» — игнорируется); запись во время обработки.

- `jobs`: порядок доставки при разной скорости задач.
