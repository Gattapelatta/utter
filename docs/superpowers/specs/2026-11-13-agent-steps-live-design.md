# Шаги Claude Code в острове вживую — спецификация

**Дата:** 2026-11-13. **Ветка:** `feat/agent-steps-live` (от `main`). **Основа:** «Капля и ИИ-агенты» — `2026-11-09-agent-drop-design.md` (§3.2 п. 2 этот документ заменяет).

## 1. Зачем

Слова пользователя: при наведении на остров, пока работает Claude Code, видно, что Claude делает прямо сейчас — выполнен шаг 1, шаг 2, что он делает на шаге 3; «ощущение, что капля следит за каждым этапом работы Claude Code». Сейчас весь план висит «шаг 0 из 9» до конца работы.

Успех: во время работы Claude Code остров при наведении показывает номер текущего шага, прошлый шаг, текущий шаг с действием, меняющимся на лету, и следующий шаг; номер растёт вместе с работой Claude.

## 2. Что выяснили замером (2026-11-13)

Записи 40 последних сессий Claude Code на Mac пользователя (`~/.claude/projects/-Users-gattapelatta-Desktop-Translate/*.jsonl`), вызовы инструмента плана приложения Claude (`mcp__ccd_turn__update_plan`), 332 вызова:

| Вид вызова | Сколько | Есть ли список |
|---|---|---|
| `{items, scope}` / `{items}` — весь план | 159 | да |
| `{advance: true}` — «следующий шаг» | 90 | нет |
| `{done: [n], start: m}` — не по порядку | 64 | нет |
| `{done: [n]}` | 19 | нет |

- Utter (`agents::event::steps`) понимает только вызовы со списком (`todos` у `TodoWrite`, `items` у плана приложения). Список почти всегда приходит в начале работы, где ещё ничего не выполнено; 173 из 332 вызовов (52 %) — отметки без списка, Utter их отбрасывает. Отсюда «0 из 9» навсегда.
- В конце работы приложение Claude отмечает все шаги вызовом `mcp__ccd_turn__wrap_up`; хук `PostToolUse` его не слушает (`STEPS_MATCHER = "TodoWrite|mcp__ccd_turn__update_plan"`).
- `TodoWrite` (Claude Code в Терминале) всегда шлёт весь список с состояниями (`pending` / `in_progress` / `completed`) — с ним всё работает уже сейчас, кроме показа названий.
- Названия шагов есть в списке (`content`), но Utter их выбрасывает: в строку агента идёт только `steps: (done, total)`.
- `UserPromptSubmit` (каждое сообщение пользователя, в т. ч. ответ «Да, верно» посреди задачи) стирает шаги (`registry` → `row.steps = None`), а следующая отметка без списка уже не к чему применить.

## 3. Что делаем

### 3.1 Вид — «Лесенка» (выбор пользователя 2026-11-13, макет в виджете `utter_island_agent_steps_options`, вариант C)

Остров при наведении на ушки, первая (самая срочная) строка агента, у которого есть план:

```
<проект> Claude Code · 3 из 9
✓ Посмотреть карточку                          ← серый (DIM), прошлый шаг
› Показать варианты строки · читает event.rs   ← яркий текущий шаг, действие серым
  Написать спецификацию                        ← бледный, следующий шаг
```

- Число в заголовке — **номер текущего шага** (раньше было число выполненных), как на макете: «3 из 9» без слова «шаг» — `agents.step` становится «{n} из {m}» / «{n} of {m}».
- Действие — последнее из `actions` (то, что уже показывается: «читает event.rs», «запускает pnpm test»), со строчной буквы после «·». Меняется на лету с каждым `PreToolUse`.
- Названия шагов — как их написал Claude, одной строкой, длинные обрезаются «…» (как сейчас строки действий). Текущий шаг обрезается раньше действия: название сжимается, действие видно, пока хватает места (минимум ~40 % строки под название).
- Высота: заголовок + до трёх строк — остров выше нынешнего на одну строку (16 pt). Это согласовано с пользователем (вариант C), больше ничего в форме острова не меняется.

### 3.2 Крайние случаи (утверждено пользователем 2026-11-13)

1. **Первый шаг:** прошлого нет → текущий и следующий (две строки).
2. **Последний шаг:** следующего нет → прошлый и текущий.
3. **Все шаги готовы:** одна строка «✓ Все {m} шагов готовы» / «✓ All {m} steps done» (формы множественного числа — как в других строках `agents.*`); заголовок без «· n из m». Дальше как раньше: «закончил» по `Stop`.
4. **Нет плана** (короткая задача): как сейчас — «✓ Прочитал …» и «› Правит …» (`pastOf`), заголовок без шага.
5. **Нет текущего шага** (`in_progress` ни у кого, но есть невыполненные): текущим считается первый невыполненный, номер — его.
6. **Несколько агентов:** «Лесенка» только у первой строки. У остальных — ровно одна строка: точка состояния, проект (жирным) и серым текущий шаг («· 3 из 9 · Показать варианты»), без плана — последнее действие, ничего нет — имя агента. Сейчас у них заголовок и до двух строк действий — остров при нескольких агентах станет ниже нынешнего.
7. **Новая задача:** пришёл новый список — старый заменяется сразу. Сообщение пользователя (`UserPromptSubmit`) стирает план, **только если все его шаги уже готовы** (задача закончена). Незаконченный план переживает ответы пользователя посреди работы («Да, верно»): иначе следующая отметка «следующий шаг» не к чему применить (§2). Новая задача в приложении Claude всегда начинается с нового списка (правило приложения), в Терминале — с нового `TodoWrite`, так что старый план исчезает сразу и тут.
8. **Codex** — без изменений (шагов не присылает).

### 3.3 Откуда шаги (как Utter их отслеживает)

Utter хранит у каждой сессии сам список: `plan: Vec<PlanStep { title, status }>` (`status`: `pending` / `active` / `done`), и применяет к нему события:

| Событие (`PostToolUse`) | Что делает с планом |
|---|---|
| `TodoWrite {todos}` | заменить весь список (`content` → `title`, `status` как есть) |
| `update_plan {items}` (с `scope` или без) | заменить весь список (`content`, `status`) |
| `update_plan {advance: true}` | текущий (`active`) → `done`; первый `pending` после него → `active` (нет активного — первый `pending` становится `active`) |
| `update_plan {done: [i…], start: k}` | шаги `i` (счёт с 1) → `done`; если есть `start` — шаг `k` → `active`, остальные `active`, не попавшие в `done`, → `pending` (у приложения всегда один активный шаг) |
| `wrap_up` без вопроса пользователю | все шаги → `done` |
| `wrap_up` с вопросом (`ask` не пустой) | ничего: это пауза, после ответа Claude продолжает тот же план (финальное ревью 2026-11-13) |

- Номера вне списка, отметка без списка, `wrap_up` без плана — пропускаются (ничего не ломают).
- Список ограничен 50 шагами, название — 200 символами (защита от мусора; длиннее не бывает).
- Хук: `STEPS_MATCHER` → `"TodoWrite|mcp__ccd_turn__update_plan|mcp__ccd_turn__wrap_up"`. Установщик уже переписывает свою группу при запуске Utter (`install.rs`), так что у пользователя хук обновится сам после установки новой версии.

## 4. Устройство

- **`agents/event.rs`:** `EventKind::Steps { done, total }` заменяется на `EventKind::Plan(PlanUpdate)`, где `PlanUpdate` — `Replace(Vec<PlanStep>)` / `Advance` / `Mark { done: Vec<u32>, start: Option<u32> }` / `Finish`. Разбор — чистая функция по `tool_name` и `tool_input`.
- **`agents/plan.rs` (новый, чистый):** `PlanStep`, `PlanStatus`, `apply(plan: &mut Vec<PlanStep>, update: PlanUpdate)`; без времени и системы — легко тестировать.
- **`agents/registry.rs`:** `AgentRow.steps: Option<(u32,u32)>` → `AgentRow.plan: Vec<PlanStep>` (пустой — нет плана); `Started` стирает план только если все шаги `done` (§3.2 п. 7). Для страницы `plan` уходит целиком (≤ 50 коротких строк — дёшево; канал `overlay://agents` уже шлёт строку целиком).
- **Страница:** `lib/types.ts` — `AgentRow.plan: { title: string; status: "pending" | "active" | "done" }[]`; чистая функция `ladderOf(plan) → { n, m, prev?, current?, next?, allDone }` (в `overlay/agents/agentIsland.ts` или рядом, Vitest); `AgentList` рисует «Лесенку» у первой строки и одну строку у остальных; `agentHeight` считает высоту по тем же правилам (сейчас `TITLE_H + min(2, actions) * LINE_H`).
- **i18n:** `agents.all_steps_done` (RU/EN, с формами числа).

## 5. Ошибки

- Странный ввод инструмента плана (не массив, нет `status`, неизвестный статус) → шаг считается `pending`; совсем без списка — событие пропускается, как сейчас.
- Отметка пришла раньше списка (Utter запустили посреди работы Claude) → пропускается; план появится со следующим списком.
- Сессия без событий 30 мин гаснет вместе с планом (как сейчас).

## 6. Проверки

- **Rust (TDD):** разбор всех пяти видов событий плана (образцы — реальные вызовы из замера §2); `plan::apply` — продвижение, «не по порядку», `wrap_up`, номера вне списка, отметка без плана; реестр — `Started` стирает только готовый план, новый список заменяет старый; установщик пишет новый `STEPS_MATCHER` и обновляет старый.
- **Vitest:** `ladderOf` — все случаи §3.2 (первый, последний, все готовы, нет плана, нет активного); `AgentList` — лесенка у первой строки, одна строка у остальных; `agentHeight` совпадает с нарисованным.
- **Вживую (коротко, без диктовки — пользователь устал от тестовых кругов):** эта же сессия Claude ведёт план по шагам, а снимок острова (`screencapture -l`, окно острова) при наведении показывает растущий номер и названия шагов. Наведение — рукой пользователя один раз, или `debug-eval`/отладочный файл, если наведение можно изобразить без руки (проверяется в плане).

## 7. Не входит

Бегущая строка и полоска прогресса (варианты A и B — отклонены); шаги у Codex; шаги в карточке «закончил»; подзадачи (`Task`/субагенты) как отдельные шаги; выпуск новой версии (только с «да» пользователя).

## 8. Итоги реализации (2026-11-13)

- **Наведение без руки пользователя:** Utter опрашивает положение курсора, поэтому `CGWarpMouseCursorPosition` к ушкам (центр окна острова по x, y ≈ 12) открывает остров; инструмент в scratchpad — `hover x y секунды`, курсор возвращается на место.
- **Финальное ревью (2026-11-13):** приложение Claude зовёт `wrap_up` в конце *каждого* ответа, также когда спрашивает пользователя; после ответа Claude продолжает тот же план отметками (`done`/`start`), а Utter уже стёр его как готовый — «Лесенка» терялась в ~17 % ответов посреди работы (замер ревьюера по 18 сессиям). Исправлено: `wrap_up` с вопросом (`ask`) план не закрывает (13 из 15 таких случаев); остаток — `wrap_up` без вопроса посреди задачи — до следующего списка показывает действия без плана.
- **Замечено:** длинная команда Bash занимает свои 60 % строки, и название шага режется рано («Сборка и живая п…»). Решение по ширине — за пользователем.
- Не проверено вживую: `TodoWrite` из Claude Code в Терминале (разбор покрыт тестами); несколько агентов одновременно; «все шаги готовы» на острове (между `wrap_up` и `Stop` остров не наводили).
