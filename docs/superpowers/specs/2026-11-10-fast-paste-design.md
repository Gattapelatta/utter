# Utter — быстрая вставка после диктовки: всё готово заранее

**Дата:** 2026-11-10
**Статус:** утверждено в разговоре, ждёт проверки пользователем
**Ветка:** `feat/fast-paste`
**Дополняет:** `2026-11-04-live-dictation-design.md` (заменяет там §4.3 строку «Перевод куска не пришёл за 3 с» и §5.6 «Попытки в конце»)

## 1. Зачем

Пользователь: «очень часто долго вставляется текст после того, как я отпустил кнопку; если так будет постоянно, в диктовке нет смысла». Цель — **текст вставляется как можно быстрее после отпускания, целевой предел 1 с**, только на Google (одна кнопка, один ключ: Groq отклонён — у пользователя он не заработал, а второй ключ при знакомстве с программой не нужен).

**Критерии успеха** (замеряются по журналу, §8):
- Диктовка с чисткой: «отпустил → вставлено» **≤ 1,0 с** всегда, кроме случаев, когда не пришёл даже распознанный текст (тогда — как сейчас, пакетный путь).
- Диктовка с чисткой: в обычный час Google ≥ 90 % фраз вставлены очищенными (метка «без обработки» в Истории — у остальных).
- Перевод: медиана ≤ 1,0 с; предел ожидания 4 с, дальше — запасной путь; текст не теряется.
- Диктовка без чистки — без изменений (~0,5 с).

## 2. Что замерено перед решением (2026-11-10, Mac пользователя, через его VPN)

| Проверка | Результат |
|---|---|
| Журнал, 11 диктовок 10.11 | распознаватель отдаёт итог за 0,2–0,8 с; всё остальное — чистка: 7 из 11 дольше 1,5 с, самые долгие 5,8 / 7,4 / 8,8 с |
| Почему 8,8 с при пределе 3 с | ошибка: после 3 с без ответа `finish_text` запускает **второй круг** чистки по маршрутам (подстраховка 2,5 с, предел 10 с на запрос) и ждёт его без общего предела |
| `cleanup_latency_spread`, 16 раундов, вечер | `3.5-flash-lite`: медиана 1,08 с, макс 2,1 с, ≤ 1 с — 7 из 16; `3.1-flash-lite`: 13 из 16 — 503 или молчание 10 с; `3.6-flash`: 1,2–1,7 с (20 запросов в день) |
| `fast_text_candidates`, 8 раундов | дорога до Google и обратно **0,11–0,12 с** (VPN не причина); `3.5-flash-lite` 0,75–6,7 с — медленные ответы идут полосой; `gemma-4-26b` всегда «думает», 6–8 с, потом 503; `gemma-4-31b` — 503 на каждый запрос |
| Режим распознавателя `SMART` | снова «по продам» вместо «по продажам» — для чистки не годится; `VERBATIM` — со знаками, цифрами и «ё», без ошибок |
| Агенты (`agent summary`) | ходят в ту же `3.5-flash-lite` тем же ключом; в часы торможения тоже упирались в свой предел 3 с |

Вывод: ждать Google **после** отпускания — это всегда ≥ 1,5 с (0,5 с итог распознавателя + ~1 с модель). Значит, к отпусканию почти всё должно быть уже готово, а на остаток — жёсткий предел.

## 3. Решения пользователя (2026-11-10)

1. Только Google; второй сервис (Groq) не добавляем.
2. Чистить по ходу речи — каждую фразу сразу, параллельно; последнюю фразу — заранее.
3. Диктовка: если через 1 с после отпускания чистка не пришла — вставлять как есть (со словами-паразитами).
4. Перевод: тоже как можно быстрее; вставить непереведённое нельзя — ждём, с пределом.
5. Фраза без чистки — без всплывающего сообщения, только метка «без обработки» в Истории.

## 4. Поведение

Термины: **фраза** — чистовой кусок распознавателя (`LiveEvent::Segment`, приходит на каждой паузе в речи); **хвост** — последний черновой кусок (`interim`), у которого ещё нет чистового; **обработка** — чистка (Диктовка) или перевод (Перевод) текстовой моделью.

### 4.1 Пока пользователь говорит

1. **Каждая фраза — сразу в обработку**, не пачкой раз в 4 с. Запросы идут параллельно: медленный запрос не задерживает следующие.
2. **Лимит запросов.** Бесплатный ключ даёт `3.5-flash-lite` 15 запросов в минуту на все диктовки и агентов вместе. Utter ведёт общий счётчик (§5.2): во время речи запрос уходит, только если в минуте остаётся место **сверх запаса в 3 запроса** на конец диктовки; иначе фраза ждёт и уходит вместе со следующей одним запросом.
3. **Зависший запрос.** Нет ответа 2,5 с — фраза отправляется ещё раз (запасная Lite-модель, если она здорова, §4.4; иначе свежий запрос к основной); первый ответ побеждает, остальные отменяются. Ошибка — повтор сразу. Повтор тоже берёт место в счётчике.
4. **Последняя фраза заранее.** Если хвост не пуст и микрофон не слышит голоса 0,4 с (та же проверка, что `quiet_tail`), хвост сразу уходит в обработку — «догадка». Пришёл чистовой кусок с тем же текстом (сравнение без регистра и знаков, `pipeline::normalize`) — догадка становится запросом этой фразы, нового запроса нет. Текст другой (договорил, Google поправил слова) — фраза уходит обычным порядком, догадка отменяется. Одновременно не больше одной догадки; новая — только для изменившегося хвоста.

### 4.2 После отпускания — Диктовка

1. **В момент отпускания** хвост (если не пуст и для него нет догадки с тем же текстом) сразу уходит в обработку как догадка — не дожидаясь чистового куска (~0,5 с).
2. **Две попытки сразу.** Фразы, ещё не отправленные (ждали места в счётчике), уходят **одним** запросом сразу в две попытки: основная модель + запасная Lite, если она здорова, иначе два свежих запроса к основной; хвост — отдельной догадкой (п. 1), тоже в две попытки (отдельно — чтобы пришедший чистовой кусок можно было сверить с догадкой). Фразы, уже ждущие ответа, получают по одной дополнительной попытке — пока есть место в счётчике, от самой старой. Запас в 3 запроса (§4.1 п. 2) — для этого.
3. **Предел 1,0 с от отпускания.** Текст собирается, как только всё готово, но не позже предела:
   - фраза с ответом → обработанный текст;
   - фраза без ответа → её распознанный текст (`VERBATIM`: со знаками и цифрами), из которого убраны только явные звуки-паразиты (§5.4);
   - хвост без чистового куска → последний черновой текст (как сейчас в `final_text`).
   Ожидание итога распознавателя тоже укладывается в предел: `FINAL_WAIT` для Диктовки с чисткой ≤ предела.
4. Хоть одна фраза без обработки → запись в Истории со статусом «без обработки» (`EntryStatus::Degraded`), **а Капля показывает обычное «Готово»** (решение 5). Все фразы без обработки — так же.
5. **Второго круга нет:** путь `Unfinished` → `finish_text` для Диктовки убирается.

### 4.3 После отпускания — Перевод

1. Пп. 1–2 из §4.2 — так же.
2. Текст вставляется, когда переведены все фразы. Предел ожидания **4 с** от отпускания; лестница попыток для неотвеченной фразы — сразу две (п. 2), через 1 с ещё одна свежая к основной, ошибка — следующая сразу.
3. Через 4 с без полного перевода — запасной путь, как сейчас: пакетный перевод записанного звука (`process_capture` с маршрутами). Отдельный круг текстовых запросов по маршрутам (`finish_text_work`, первая половина) убирается — он и давал лишние секунды.

### 4.4 Запасная модель и её здоровье

- Запасная Lite (`GEMINI_BACKUP_LITE_MODEL`) берётся в попытки, только пока она «здорова»: ошибка или нет ответа за 2,5 с → 10 минут её не трогаем (тот же механизм, что `RouteHealth` маршрутов, общий для диктовок). Пока она больна, вместо неё — второй свежий запрос к основной.
- `3.6-flash` в живой путь не берём (1,2–1,7 с и 20 запросов в день — до предела не успеет и съест дневной лимит).

### 4.5 Агенты

Резюме агента тоже берёт место в общем счётчике запросов. Места нет (сверх запаса) → резюме без модели, как при выключенном «умном» резюме. Так агент не отнимает запас у диктовки.

### 4.6 Что не меняется

Диктовка без чистки, пакетный путь (Groq/OpenAI, абзацы, сбой соединения), Капля и остров, черновик в острове, порядок вставки по очереди, «Повторить» в Истории, счётчики использования (каждый запрос считается, догадки и повторы тоже).

## 5. Устройство

### 5.1 `live/translate.rs` → обработчик фраз

`SegmentTranslator` переписывается под §4.1–4.3 (чистая логика, часы — `tokio::time`, тестируется на остановленных часах):
- фразы с номерами; у каждой — состояние: ждёт / в работе (одна или несколько попыток) / готова (текст) / без ответа;
- `push(segment)`, `on_interim(text)`, `on_quiet()`, `poll(now)` — во время речи; `release()` и `finish(deadline, mode)` — в конце;
- `finish` для Диктовки возвращает текст по §4.2 п. 3 и признак «есть фразы без обработки»; для Перевода — текст или ошибку по §4.3;
- запросы выдаются через счётчик §5.2 и выбор модели §4.4; каждый запрос считается в `requests()`;
- в журнал: `timing: live piece processed piece_ms attempts chars`, `timing: live guess hit|miss`, `timing: live end ready_ms pieces raw_pieces`.

Имя модуля можно сменить на `live/process.rs` (он и чистит, и переводит) — решение плана.

### 5.2 Общий счётчик запросов — `providers/budget.rs`

- Скользящее окно 60 с, по одному на модель (`3.5-flash-lite`, `3.1-flash-lite`); предел 14 в минуту (один в запас от 15).
- `try_take(model, priority)`: `Speech` (во время речи) — только если после взятия остаётся ≥ 3; `End` (конец диктовки, догадки) — пока есть место; `Agent` — как `Speech`.
- Живёт в `Arc<Mutex<_>>` у оркестратора (как `RouteHealth`), общий для диктовок, повторов и агентов. Лимиты — в `providers/defaults.rs`.
- Ответ 429 → окно этой модели считается полным до `retry_after` (или 60 с).

### 5.3 `live/run.rs`

- Голос: проверка «тишина 0,4 с при непустом хвосте» во время речи → `on_quiet()`.
- Отпускание → `release()` обработчика; для Диктовки с чисткой `FINAL_WAIT` и ожидание обработки укладываются в один предел 1,0 с.
- `LiveOutcome::Final` получает признак «частично без обработки» (`partial`); `Unfinished` остаётся только для Перевода.

### 5.4 Звуки-паразиты без модели — `pipeline/fillers.rs`

- Убираются только отдельные слова целиком (без учёта регистра): «э», «ээ», «э-э», «э-э-э», «эм», «эмм», «мм», «ммм», «хм»; для английской речи — «um», «uh», «erm». Вместе со словом — запятая после него и лишний пробел; первая буква фразы снова заглавная.
- «ну», «типа», «как бы», «а» не трогаются (бывают по смыслу).
- Применяется только к фразам без обработки (§4.2 п. 3).

### 5.5 Оркестратор

- `start_live`: обработчик получает счётчик и здоровье запасной модели.
- `live_done(Final { partial: true })` → `JobOutput { degraded: true }` для Истории, но состояние Капли — `Done { degraded: false }` (§4.2 п. 4). Нужен отдельный признак, чтобы не сломать нынешнее «Вставлено без обработки» пакетного пути.
- `finish_text`/`finish_text_work`: для Диктовки не вызываются; для Перевода — сразу пакетный путь (§4.3 п. 3).

## 6. Риски

| Риск | Мера |
|---|---|
| Чистка по фразам теряет связь между ними («в среду… нет, в четверг» через паузу) | принято; соседние фразы и так склеиваются, когда счётчик полон |
| Догадка часто промахивается (Google правит слова в чистовике) | замер `guess hit/miss`; промах стоит один запрос, а не время |
| Долгая диктовка без пауз упирается в 14 запросов в минуту | фразы склеиваются; запас 3 запроса всегда на конец |
| Google тормозит полосой — все попытки медленные | Диктовка: предел 1 с и вставка как есть; Перевод: ждём до 4 с — потолок бесплатного Google, принято пользователем |
| Удаление «э»/«мм» задевает настоящее слово | только отдельные слова из короткого списка; тесты на русских и английских фразах |

## 7. Вне рамок

Groq и другие сервисы, платный ключ Google, режим `SMART`, абзацы на лету, Windows.

## 8. Проверка

**Автотесты (TDD, остановленные часы):** фраза уходит сразу; параллельные запросы — медленный не держит следующий; счётчик: запас 3, склейка фраз при полном окне, 429 закрывает окно; повтор через 2,5 с и сразу после ошибки; догадка: попадание, промах, договорил после паузы; отпускание: хвост сразу, две попытки; предел 1 с: смесь готовых и неготовых фраз, хвост без чистового; Перевод: ждёт все фразы, 4 с → пакетный путь; второго круга нет; здоровье запасной модели; агент без места → резюме без модели; паразиты: список, регистр, запятая, заглавная, «ну» остаётся; `partial` → История «без обработки», Капля «Готово».

**Живые замеры (`#[ignore]`, ключ пользователя, с его согласия):** `cleanup_latency_spread`, `fast_text_candidates`.

**Живая проверка с пользователем:** 20+ диктовок — короткие, длинные 30–40 с, с паузой перед отпусканием и без, Диктовка и Перевод; по журналу — медиана и максимум «отпустил → вставлено», доля фраз без обработки, попадания догадок, 429. Результаты — сюда, в новый §9.

**Бюджеты:** в простое ничего не меняется.
