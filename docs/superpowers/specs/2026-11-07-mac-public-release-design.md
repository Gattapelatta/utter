# Utter — публичный выпуск для Mac (План 3)

**Дата:** 2026-11-07 · **Статус:** утверждено пользователем в разговоре 2026-11-07 · **Ветка:** `feat/release-mac`

Основная спецификация — `2026-10-06-utter-design.md`; этот документ уточняет её §10 («Сборка и выпуск») для первого публичного выпуска только для Mac. Windows — отдельным планом позже.

## 1. Цель

Любой человек со страницы Utter на GitHub скачивает файл, ставит Utter на Mac и дальше получает обновления кнопкой «Установить». У Utter своя иконка и понятная страница с анимацией.

**Готово, когда:**
1. Одна команда на Mac пользователя выпускает версию: проверка → сборка → подпись → выпуск на GitHub.
2. Установленный Utter находит новую версию и ставит её; разрешения микрофона и «Универсального доступа» после обновления остаются.
3. Репозиторий открыт, в его истории нет ключей и паролей.
4. README (EN + RU) с анимацией острова и инструкцией установки; у приложения новая иконка.

## 2. Решения пользователя (2026-11-07)

| Вопрос | Решение |
|---|---|
| Порядок | Сначала выпуск для Mac, Windows — следующим планом |
| Для кого | Всем сразу (открытый репозиторий, публичный выпуск) |
| Подпись | Бесплатная своя («Utter Dev», самоподписанная). Developer ID ($99/год) — позже, если Utter окажется полезен людям; сборку готовим к переходу |
| Где выпускать | На Mac пользователя одной командой; ключи не покидают Mac. GitHub только прогоняет тесты |
| Состав | Выпуск + автообновление + иконка + README с анимацией. Мелочи финального обзора Плана 2 — позже (кроме установки обновления посреди диктовки — §3.3) |
| Intel | Собираем универсальное приложение (Apple Silicon + Intel); вживую на Intel не проверено — так и пишем в README |
| Объяснения | Пользователь просит объяснять очень просто, без терминов, и всегда говорить, что ему сделать |

## 3. Поведение

### 3.1 Выпуск версии — `scripts/release.sh <версия> [--dry-run]`

Шаги по порядку; любой сбой останавливает скрипт, ничего не опубликовав:

1. **Проверки:** ветка `main`, нет несохранённых изменений, `main` совпадает с `origin/main`, тега `v<версия>` ещё нет, версия выше текущей; файл заметок `docs/releases/<версия>.md` существует и не пуст; `cargo test --lib`, `cargo clippy --all-targets` (0 предупреждений), `pnpm test` — зелёные; сертификат «Utter Dev» и ключ обновлений `~/.tauri/utter.key` на месте; установлены цели `aarch64-apple-darwin` и `x86_64-apple-darwin`.
2. **Версия** записывается в `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` (+ `Cargo.lock`), `package.json`; коммит `release: v<версия>`.
3. **Сборка** `universal-apple-darwin` **без** функции `debug-eval` (она только для разработки — находка m7 обзора), подпись «Utter Dev» с идентификатором `app.utter.desktop` (как в `dev-bundle.sh`, иначе разрешения у людей не переживут обновление).
4. **Файлы выпуска** — все из уже подписанного приложения:
   - `Utter_<версия>_universal.dmg` — первая установка (перетащить в «Программы»);
   - `Utter.app.tar.gz` + `.sig` — архив обновления и его подпись ключом обновлений (Tauri updater, minisign);
   - `latest.json` — `{version, notes, pub_date, platforms: {darwin-aarch64, darwin-x86_64}}`, обе платформы указывают на один универсальный архив.
5. **Самопроверка файлов** перед публикацией: в `.dmg` и в архиве приложение подписано «Utter Dev» (`codesign -dv`: Authority, Identifier), содержит обе архитектуры (`lipo -archs`: `x86_64 arm64`), подпись архива сходится с открытым ключом из `tauri.conf.json`, в `latest.json` версия и ссылки совпадают с файлами.
6. **Публикация** (не при `--dry-run`): тег `v<версия>`, `git push` ветки и тега, `gh release create v<версия>` с тремя файлами и заметками; выпуск — обычный (не «предварительный»), иначе `releases/latest/download/latest.json` его не увидит.

`--dry-run` делает шаги 1, 3–5 во временной папке и не меняет версию, не коммитит и ничего не публикует.

**Developer ID позже:** если заданы переменные Apple для нотаризации (`APPLE_SIGNING_IDENTITY`, `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID`), скрипт подписывает этим сертификатом с hardened runtime и отправляет на нотаризацию; без них — «Utter Dev». В этом плане ветка Developer ID только описана и проверяется на отсутствие переменных (купленного сертификата нет).

### 3.2 Что видит человек

- **Первая установка:** скачал `.dmg`, перетащил Utter в «Программы». При первом запуске macOS 15 блокирует приложение без подписи Apple (обход правым кликом в macOS 15 убран). README по шагам: Системные настройки → Конфиденциальность и безопасность → «Всё равно открыть» → «Открыть». Один раз.
- **Обновления:** Utter сам находит новую версию (План 2, Task 12): «О приложении» и трей предлагают «Установить». Архив скачивается не браузером — macOS его не блокирует. Разрешения сохраняются (тот же сертификат и идентификатор).
- **Ограничение бесплатной подписи:** после каждого обновления macOS один раз спрашивает доступ к Связке ключей (где лежит API-ключ) — «Разрешать всегда». README это объясняет; уйдёт с Developer ID.

### 3.3 Обновление не прерывает диктовку (находка m4 финального обзора Плана 2)

«Установить» во время записи или обработки не перезапускает Utter: установка ждёт, пока запись закончится и все тексты вставятся, затем ставится. В «О приложении» в это время — «Установлю после диктовки». Новая запись во время скачивания ждать не заставляет: скачивание идёт, а перезапуск — только в простое.

### 3.4 Открытый репозиторий

- **Перед открытием** — проверка всей истории git на секреты: ключи Gemini (`AIza…`), Groq (`gsk_…`), OpenAI (`sk-…`), закрытые ключи (`BEGIN … PRIVATE KEY`, содержимое `utter.key`), пароли/токены в настройках. Найденное — стоп и разговор с пользователем (переписывание истории — только с его согласия).
- `LICENSE` (MIT), `README.md` (RU, главная — решение пользователя 2026-11-07: заходить будут в основном из России), `README.en.md` (EN).
- `.github/workflows/ci.yml`: на push и PR — `cargo test --lib`, `cargo clippy --all-targets -D warnings`, `pnpm test`, `pnpm build` на `macos-latest`. Секретов не требует.
- Открытие (`gh repo edit --visibility public`) — **только после явного «да» пользователя** в чате, после первого выпуска в черновике проверки (§5).

### 3.5 README

Две страницы — `README.md` (RU, открывается первой) и `README.en.md`, ссылки друг на друга вверху. По §10 основной спецификации, без Windows:
- первый экран: анимация острова (GIF), строка «Free. Your own key. No servers.» / «Бесплатно. Свой ключ. Без наших серверов.», кнопка-ссылка на последнюю версию;
- что умеет (диктовка, перевод в двух стилях, черновик на лету, Капля в чёлке);
- установка в 3 шага + «Всё равно открыть» + разрешения (микрофон, Универсальный доступ) + ключ Gemini за минуту;
- приватность (звук идёт напрямую провайдеру, ключ — в Связке ключей, наших серверов нет; на бесплатном тарифе Google может использовать данные для улучшения продуктов);
- вопросы и ответы (лимиты бесплатного тарифа, VPN там, где Gemini недоступен, вопрос Связки ключей после обновления, Intel не проверен);
- планы (Windows), как помочь проекту.

**Анимация:** запись острова на экране пользователя через отладочный «проигрыватель» `debug-draft.txt` (рост острова, черновик, «Готово», сворачивание в ушки) — `screencapture -v` области у чёлки, перевод в GIF своим маленьким инструментом на Swift (ImageIO; `ffmpeg` на Mac нет). Цель — ≤ 3 МБ, 2× для Retina, без звука. Второй ролик (по желанию) — живая диктовка пользователя в Notes.

### 3.6 Иконка

- Капля (тот же контур и глаза, что в `Drop.tsx`) на квадрате-«скругле» macOS (сетка 1024 × 1024, поле 824, радиус по шаблону Apple), без текста.
- 3 варианта показываются пользователю картинками (виджет): например, белая Капля на чёрном (как остров), чёрная Капля на светлом, Капля с мягким ореолом на тёмно-синем градиенте. Пользователь выбирает; меняется только то, что он просит (память `change-only-what-asked`).
- Выбранный вариант — SVG в `docs/design/icon.svg` → PNG 1024 (рендер WebKit на Mac) → `pnpm tauri icon` создаёт `icns`/`ico`/PNG в `src-tauri/icons/`. Иконка в строке меню не меняется.

## 4. Устройство

- `scripts/release.sh` — короткая оболочка (bash), вызывает команды по порядку. Вся проверяемая логика — в модулях TypeScript `scripts/release/*.ts` (Node 24 запускает `.ts` без сборки; тесты — Vitest рядом, `*.test.ts`): сравнение версий, запись версии в три файла, сборка `latest.json`, разбор вывода `codesign`/`lipo`, проверки шага 1. Публикация — через `gh`.
- `src-tauri/src/app/updates.rs` (+ оркестратор): «установить, когда простаивает» — чистая функция решения (`занят?` → ждать) и сигнал «стал свободен» от оркестратора.
- `scripts/tools/mov2gif.swift` — видео → GIF (ImageIO), с параметрами кадров/масштаба.
- `docs/design/icon.svg`, `src-tauri/icons/*`.
- `README.md`, `README.en.md`, `LICENSE`, `.github/workflows/ci.yml`, `docs/releases/<версия>.md`.

## 5. Проверка

- **Автотесты (TDD):** сравнение и запись версий, сборка `latest.json` (обе платформы, URL, подпись из `.sig`), разбор `codesign`/`lipo`, отказ скрипта на каждой проверке шага 1 (грязное дерево, не `main`, тег существует, версия не выше, нет заметок); «установить в простое» (во время записи не ставится; ставится, когда очередь пуста).
- **Пробный выпуск** `--dry-run` на Mac пользователя: файлы созданы и прошли самопроверку §3.1.5; `.dmg` открывается, приложение из него запускается и работает.
- **Живая проверка обновления:** первая публичная версия `0.2.0` → установка из `.dmg` «как новый человек» (с «Всё равно открыть») → выпуск `0.2.1` → Utter сам находит и ставит её; после перезапуска диктовка работает без новых разрешений «Универсального доступа» (вопрос Связки ключей ожидаем). Скачивать выпуски могут только из открытого репозитория, поэтому порядок такой: пробный выпуск `--dry-run` и установка из его `.dmg` → открытие репозитория (с согласия пользователя) → выпуск `0.2.0` → выпуск `0.2.1` и проверка обновления. Репозиторий пока никому не известен, так что неудачный первый выпуск можно убрать без вреда.
- **Не проверяется:** Intel-Mac (нет устройства), macOS 13–14 (у пользователя 15).

## 6. Вне рамок этого плана

Windows; Developer ID и нотаризация (только подготовка); мелочи финального обзора Плана 2 (кроме §3.3); `CONTRIBUTING.md` и шаблоны issue (по §10 основной спецификации — следующим шагом после первого выпуска); сайт-лендинг; статистика скачиваний.

## 7. Что нужно от пользователя

1. Один раз сохранить копию сертификата «Utter Dev» вместе с закрытым ключом в «Пароли» (как ключ обновлений) — по шагам с картинками.
2. Выбрать иконку из трёх вариантов.
3. «Да» на открытие репозитория и на каждый выпуск.
4. Установить первую версию «как новый человек» и нажать «Установить обновление» на второй.
