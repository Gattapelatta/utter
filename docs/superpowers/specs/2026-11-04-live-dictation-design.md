# Utter — диктовка на лету: черновик в поле, чистовик после отпускания

**Дата:** 2026-11-04
**Статус:** утверждено в разговоре, ждёт проверки пользователем
**Дополняет:** `2026-10-06-utter-design.md` (§3.4, §7, §8.4 ссылаются сюда)

## 1. Зачем

Сейчас Utter записывает фразу целиком и отправляет её только после отпускания клавиши. Текст появляется через 1,2–1,8 с в хороший день и не появляется совсем, когда Google тормозит (2026-11-04: `gemini-3.5-flash-lite` отвечала ~20 с, все диктовки обрывались по таймауту 10 с с неверным «Нет соединения»). Пользователь хочет ощущение голосового ввода Claude: **текст виден прямо во время речи, а сразу после отпускания становится окончательным**.

**Критерии успеха** (замеряются, §8):
- черновик в поле отстаёт от речи не больше ~0,7 с;
- чистовик в поле через ≤ 0,8 с после отпускания (Диктовка, p50), ≤ 1,6 с (Перевод, p50);
- ни одного потерянного текста: при любом сбое срабатывает запасной путь.

## 2. Что проверено перед решением (2026-11-04, Mac пользователя, через его VPN)

Одноразовые прототипы, в продукт не вошли.

| Проверка | Результат |
|---|---|
| `gemini-3.5-transcribe-live` (WebSocket Live API), фраза 9,7 с | первые слова через 0,7 с; обновления каждые ~0,5 с; чистовик **0,41–0,47 с** после конца речи |
| Режим `SMART` | убирает «эээ», оговорки и самоисправления («во вторник, ой, нет, в среду» → «в среду»); в 2 из 2 прогонов ошибка «по продам» вместо «по продажам» и «е» вместо «ё» |
| Режим `VERBATIM` | дословно, со знаками и «ё», без ошибок на той же фразе |
| Распознавание macOS на устройстве | русский поддерживается, но **работает только при включённой Диктовке macOS** — отклонено |
| Черновик, печатаемый в поле по словам | работает в Notion и Claude, но неотличим от текста |
| Серая плашка у края поля | отклонено пользователем («странно рядом с полем»); Electron-программы (Notion, Claude) не сообщают координат курсора, только рамку поля |
| **Способ ввода (InputMethodKit), черновик как предварительный текст** | работает в Notion, Claude, Telegram: черновик подчёркнут, после утверждения — обычный текст; подключается к полю сразу, если способ ввода не переустанавливался; оформление (цвет линии, курсив, фон) программы **игнорируют** — линия у Notion/Claude синяя |
| Программное включение способа ввода | `TISRegisterInputSource` + `TISEnableInputSource` работают без похода в Системные настройки; переключение туда и обратно ~0,02 с |
| Подключение поля к новому способу ввода | без «пробуждающего» нажатия — с опозданием до конца речи или вовсе нет; с нажатием F19 (способ ввода его глотает) — сразу |

## 3. Решения пользователя (2026-11-04)

1. Вариант A: потоковое распознавание Google (`gemini-3.5-transcribe-live`), а не распознавание на Mac.
2. Черновик — **прямо в поле**, через собственный способ ввода Utter; оформление черновика — какое рисует программа (у Notion и Claude синее подчёркивание). Если разонравится — черновик без подчёркивания (обычный текст), который заменяется чистовиком в конце (запасной вариант, уже проверен прототипом).
3. Чистовая обработка включена → `SMART`, выключена → `VERBATIM`.
4. Остров у чёлки во время записи — как сейчас (Капля и таймер), без текста.

## 4. Поведение

### 4.1 Диктовка

1. Нажатие клавиши: запись стартует сразу (как сейчас), открывается потоковое соединение, Utter запоминает текущую раскладку и включает свой способ ввода, «будит» поле нажатием F19.
2. Во время речи в поле под курсором растёт **черновик** — предварительный (marked) текст, который правится по словам. Черновик = зафиксированные куски + текущий черновой кусок (§5.2).
3. Отпускание: Utter отправляет конец звука; чистовые куски приходят за ~0,4 с; черновик **утверждается чистовиком** одной операцией (`insertText` заменяет предварительный текст); раскладка возвращается.
4. Пилюля — как сейчас: «Запись» → «Готово» → ушки.

### 4.2 Перевод

- Черновик во время речи — **русский** (то, что распознано).
- Каждый чистовой кусок, как только пришёл, сразу переводится текстовой моделью (стиль «Деловой»/«Разговорный» — те же промпты, что сейчас). Переводы склеиваются строго по порядку кусков.
- После отпускания: ждём перевод последнего куска, затем утверждаем **английский** чистовик вместо русского черновика.

### 4.3 Запасные пути (текст не теряется никогда)

| Ситуация | Что делает Utter |
|---|---|
| Потоковое соединение не открылось за 3 с, закрылось с ошибкой, 429, «location not supported» | заканчивает запись как сейчас (§3.4, §3.4a — запись целиком, пакетный запрос); черновика нет или он стирается; ошибку провайдера пилюля называет честно (§8.3) |
| После отпускания чистовика нет 1,5 с | берётся то, что пришло (чистовые куски + последний черновой); если не пришло ничего — пакетный путь по записанному звуку |
| Способ ввода не подключился к полю за 0,3 с после «пробуждения» (пароли, Secure Input, редкие программы) | черновика нет; чистовик вставляется нынешней доставкой (§3.4, §8.1) |
| Фокус ушёл в другое поле или программу во время диктовки | черновик в старом поле **стирается** (способ ввода очищает предварительный текст, а не утверждает его); чистовик — в буфер обмена, пилюля «Скопировано — ⌘V» |
| Перевод куска не пришёл за 3 с | этот кусок переводится заново вместе со следующим; после отпускания ждём не дольше 3 с, иначе — пакетный перевод всего текста |
| Соединение живо, но ответа нет | запасные маршруты (§4.5); если не ответил ни один — пилюля: «Gemini отвечает слишком долго» (новый ключ ошибки `slow_provider`), а не «Нет соединения» |

### 4.5 Запасные модели — диктовка работает всегда (требование пользователя 2026-11-04)

«Человек, который нажал клавишу, 100 % должен получить текст.» 2026-11-04 основная модель `gemini-3.5-flash-lite` отвечала ~20 с, и Utter не вставил ни одной диктовки, хотя `gemini-3.5-transcribe` отвечала за 1,1 с, а `gemini-3.6-flash` — за 2–3 с.

- **Пакетный путь — список маршрутов** (в `providers/defaults.rs`, по порядку):
  1. один запрос «звук → готовый текст» на `gemini-3.5-flash-lite` (как сейчас);
  2. `gemini-3.5-transcribe` (распознавание) + чистка/перевод текста на `gemini-3.6-flash`;
  3. один запрос на `gemini-3.6-flash`.
- **Подстраховка (hedging):** если текущий маршрут не ответил за `2,5 с + 0,1 с × длительность звука`, тот же звук **параллельно** уходит по следующему маршруту; вставляется первый успешный ответ, остальные отменяются. Ошибка маршрута (429, 5xx, тайм-аут, неожиданный ответ) — сразу следующий маршрут, без ожидания.
- **Память о здоровье:** маршрут, который тормозил или ошибся, 10 минут ставится в конец списка — следующие диктовки сразу идут быстрым маршрутом.
- **На лету:** если потоковая модель не подключилась или оборвалась — запасная потоковая модель (кандидат `gemini-3.1-flash-live-preview`, если замер подтвердит, что она отдаёт `inputTranscription`), иначе — пакетный путь с подстраховкой.
- Ошибку пилюля показывает, только если не сработал **ни один** маршрут; ключ ошибки — по последней причине (`slow_provider`, `region_blocked`, `rate_limited`, `network`).
- Каждая попытка учитывается в счётчиках запросов.
- Ключ и `Unauthorized` — без перебора маршрутов (ключ один на все модели): сразу ошибка «ключ отклонён».

### 4.4 Что не меняется

Горячие клавиши, «Удержание»/«Нажатие», лимит записи 10 мин (совпадает с пределом сессии Live API), Капля и ушки, история (сохраняется чистовик), счётчики (одна диктовка = один запрос), Groq и OpenAI — пакетный путь. Windows — позже (TSF), до тех пор там пакетный путь.

## 5. Устройство

### 5.1 Потоковое соединение — `providers/gemini_live.rs`

- WebSocket `wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContent` (адрес и модель — только в `providers/defaults.rs`: `GEMINI_LIVE_URL`, `GEMINI_LIVE_MODEL = "gemini-3.5-transcribe-live"`); ключ — заголовком `x-goog-api-key` (в проверке ключ передавался параметром `key` в адресе; если заголовок сервер не примет — параметр, но тогда адрес соединения **никогда** не пишется в лог и в ошибки).
- Первое сообщение — `setup`: `model`, `generationConfig.responseModalities = ["TEXT"]`, `inputAudioTranscription { mode: SMART|VERBATIM, languageCodes: [язык речи] }` (пусто при «Авто»).
- Звук: 16-бит PCM, 16 кГц, моно, кусками по 100 мс (`realtimeInput.audio`, `mimeType: "audio/pcm;rate=16000"`). Источник — `recorder.peek(from)` раз в 100 мс; ресемплинг до 16 кГц.
- Звук, записанный до `setupComplete`, копится и досылается сразу после него.
- Конец: `realtimeInput.audioStreamEnd = true`.
- Из ответов берутся `serverContent.interimInputTranscription.text` (черновой кусок) и `serverContent.inputTranscription.text` (чистовой кусок).
- Наружу модуль отдаёт события: `Interim(text)`, `Segment(text)`, `Closed(reason)`.

### 5.2 Сборщик черновика — `live/draft.rs` (чистая логика)

- Состояние: зафиксированные черновики кусков (последний черновой текст каждого куска на момент его чистовика), текущий черновой кусок, чистовые куски.
- `draft()` = зафиксированные черновики + текущий черновой, через пробел. Чистовые куски в черновик **не подставляются** до конца — поле не «переписывается» посреди речи.
- `final_text()` = чистовые куски через пробел (+ хвостовой черновой кусок, если его чистовик не пришёл, §4.3).
- Черновик в поле обновляется не чаще раза в 100 мс и только при изменении.

### 5.3 Способ ввода — `macos/UtterIM/` (Swift, InputMethodKit)

- Отдельное приложение внутри `Utter.app/Contents/Resources/UtterIM.app`; при запуске Utter копирует его в `~/Library/Input Methods/` (если там нет или версия старше), регистрирует и включает (`TISRegisterInputSource`, `TISEnableInputSource`).
- Идентификатор `app.utter.desktop.inputmethod`; `InputMethodConnectionName` = идентификатор + `_Connection` (иначе поля не подключаются — проверено); `TISInputSourceID` = тот же идентификатор; название в меню раскладок — «Utter».
- Клавиши пропускает в программу (`handle` → `false`), кроме F19 (keyCode 80) — её глотает.
- Черновик: `setMarkedText` с атрибутом только «подчеркнуть» (`NSUnderlineStyle.single`), без цвета; чистовик: `insertText`; очистка: `setMarkedText("")`.
- `commitComposition` (программа просит закончить, например при уходе фокуса) — **очищает** черновик, а не утверждает его.
- Сообщает Utter `active {bundle id}` / `inactive` — по ним Utter замечает смену поля (§4.3).

### 5.4 Канал Utter ↔ способ ввода

- Unix-сокет `~/Library/Application Support/app.utter.desktop/im.sock`; папка `0700`, сокет `0600`; Utter — сервер, способ ввода — клиент.
- Строки JSON: Utter → способ ввода `draft {text}`, `commit {text}`, `clear`; обратно — `hello {version}`, `active {bundle}`, `inactive`.
- **Проверка собеседника обязательна** (иначе любая программа с правами пользователя печатала бы в поля через Utter, не имея доступа «Универсальный доступ»): способ ввода сверяет подпись процесса-сервера по audit token (`LOCAL_PEERTOKEN`) с требованием «идентификатор `app.utter.desktop` и тот же сертификат, что у способа ввода»; Utter сверяет подпись клиента тем же образом. При несовпадении соединение закрывается.

### 5.5 Переключатель раскладки — `output/ime.rs` (macOS, TIS)

- Старт диктовки: запомнить текущий источник ввода, выбрать «Utter», послать F19 (с `SYNTHETIC_MARK`, чтобы свой перехват его пропустил), ждать `active` до 0,3 с.
- Конец: `commit` (или `clear`), затем вернуть запомненный источник. Источник возвращается **всегда** — и при ошибках, и при отмене (Esc), и при сбое самого Utter во время диктовки (при следующем запуске, если активен «Utter», выбирается последний запомненный источник).

### 5.6 Перевод по кускам — `live/translate.rs`

- Каждый `Segment` переводится текстовым запросом (модель `GEMINI_TRANSLATE_MODEL` в `defaults.rs`, выбирается замером в плане среди `gemini-3.5-flash-lite`, `gemini-3.6-flash`, `gemini-3.7-flash`, `gemini-3.8-flash`); запросы параллельны, результат склеивается по номеру куска.

### 5.7 Оркестратор

- Новый путь «на лету» для провайдера Gemini; пакетный путь (§3.4a, `jobs`, `pipeline`) остаётся без изменений и служит запасным.
- Запись по-прежнему сохраняется целиком (для запасного пути и «Повторить» в истории).
- Новые тайминги в лог: `timing: live setup_ms`, `timing: live first interim_ms`, `timing: live release→final_ms`, `timing: live release→committed_ms`, `live fallback reason=…`.

## 6. Риски и как их закрываем

| Риск | Мера |
|---|---|
| Пункт «Utter» в меню раскладок и в переключении ⌃Пробел | осознанно принято; если пользователь выберет его вручную — клавиши проходят как обычно |
| Раскладка «застряла» на Utter | возврат в `finally`-ветке каждого исхода + при старте Utter |
| Поле подключается к способу ввода с опозданием | «пробуждение» F19 + ожидание `active` 0,3 с + запасная доставка |
| Переустановка способа ввода ломает подключение до следующего ввода | ставим только при смене версии; после установки — «разминка» (выбрать, F19, вернуть) |
| Бесплатные лимиты Live API не опубликованы | замер в плане; при 429 — пакетный путь и честное сообщение |
| `SMART` иногда ошибается в словах | принято пользователем; при выключенной чистовой обработке — `VERBATIM` |
| Google недоступен без VPN («location not supported») | как сейчас: честная ошибка провайдера |

## 7. Вне рамок

Windows (TSF), «на лету» для Groq/OpenAI, текст в острове, выбор оформления черновика в настройках, распознавание на Mac без сети.

## 8. Проверка

**Автотесты:** сборщик черновика (рост, фиксация кусков, хвост без чистовика, «не переписывать посреди речи»); разбор сообщений Live API на настоящих ответах из проверки 2026-11-04; сборка `setup` для SMART/VERBATIM/«Авто»; ресемплинг и нарезка по 100 мс; досылка звука после `setupComplete`; все строки таблицы §4.3; склейка переводов по порядку при перепутанных ответах; протокол канала и отказ при чужой подписи; возврат раскладки при каждом исходе.

**Тест с поддельным сервером Live API** (локальный WebSocket): нормальный путь, обрыв, молчание, 429.

**Живые тесты (`#[ignore]`, с ключом пользователя, только с его согласия):** задержки на фразе `tests-data/phrase-ru.wav`, замер моделей перевода.

**Ручная проверка:** Notion, Claude, Telegram, TextEdit, Safari — Диктовка и Перевод, смена окна посреди диктовки, Esc, пароль-поле, сон/пробуждение, выключенный VPN.

**Бюджеты** — §1; в простое ничего не меняется (способ ввода без диктовки — 0 % CPU).
