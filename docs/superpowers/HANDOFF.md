## Ключевые решения, принятые по ходу (их нет в исходном брейншторме)

1. **Провайдер по умолчанию — Google Gemini**, а не Groq: регистрация в Groq у пользователя зацикливалась (известная проблема Groq). Ключ Gemini — aistudio.google.com/apikey через Google-аккаунт. Groq и OpenAI остались как альтернативы.
2. **Gemini = один запрос «аудио → готовый текст»** на `gemini-3.5-flash-lite` с `thinking_level: "minimal"` (~1,3 с; лимит бесплатного тарифа 15 запросов/мин). Без чистовой обработки — `gemini-3.5-transcribe`. При лимите/сбое модели — откат на `gemini-3.5-transcribe` (текст без обработки). `gemini-3.5-flash` не используем: 5 запросов/мин и ~2 с «размышлений».
3. **Активный перехват клавиатуры** (CGEventTap не listen-only): во время записи Esc и клавиши сочетания «проглатываются» (превращаются в Null-событие — в core-graphics 0.24 `None` из колбэка = «пропустить как есть»!). Свои нажатия (⌘V, печать) Utter помечает `SYNTHETIC_MARK` в `EVENT_SOURCE_USER_DATA`.
4. **Таймаут запроса 10 с** (+5 с за минуту аудио сверх 2 мин), connect-timeout 3 с; через 4 с пилюля пишет «Жду ответа сервера…». У пользователя стоит VPN/фильтр, который принимает любые TCP-соединения, поэтому «быстрой ошибки соединения» нет.
5. **Умный пробел**: символ перед курсором через Accessibility (`AXSelectedTextRange` + `AXStringForRange`), запасной путь — помним последнюю вставку в то же приложение (2 мин).
6. **Сон/пробуждение** определяется по разрыву *настенного* времени между тиками (`Instant` на macOS во сне стоит).

## Как собирать и запускать (на Mac пользователя)

- Инструменты: Rust (`~/.cargo/bin`), Node + pnpm (`~/.local/node/bin`), GitHub CLI (`~/.local/bin/gh`). В Bash добавляй `export PATH="$HOME/.local/node/bin:$HOME/.cargo/bin:$HOME/.local/bin:$PATH" COREPACK_ENABLE_DOWNLOAD_PROMPT=0`.
- Тесты: `cargo test --manifest-path src-tauri/Cargo.toml --lib` (171 тест) и `pnpm test` (Vitest).
- Линтер: `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets` — держим 0 предупреждений.
- **Сборка для пользователя: `scripts/dev-bundle.sh`** (release, подпись сертификатом «Utter Dev» из связки ключей пользователя → разрешения Accessibility/микрофон переживают пересборки). Запуск: `open src-tauri/target/release/bundle/macos/Utter.app`. Перед пересборкой: `pkill -x utter`.
- `scripts/dev-bundle.sh --debug` + `scripts/paste-matrix.sh src-tauri/target/debug/bundle/macos/Utter.app` — автопроверка вставки в TextEdit (10 случаев; пользователь не должен трогать клавиатуру ~1 мин).
- Лог приложения: `~/Library/Logs/app.utter.desktop/utter.log` (строки `timing:` — замеры скорости по этапам).
- Тесты с `#[ignore]` трогают реальный Keychain/микрофон/сеть с ключом пользователя — запускать только с его согласия (`src-tauri/src/providers/bench.rs` — живой замер скорости Gemini).

## Как начать План 2

1. Прочитай спецификацию целиком (особенно §4 «UX-поверхности» и §5 «Визуальный дизайн» — стиль x.ai: почти чёрный фон, Geist/Geist Mono, смысловые акценты, pop-in анимации; тёмная тема по умолчанию + светлая) и этот файл.
2. Скилл `writing-plans` → `docs/superpowers/plans/YYYY-MM-DD-utter-plan-2-premium-ui.md`. Брейншторм заново не нужен — дизайн утверждён в спецификации; если появится новый вопрос дизайна — короткий вопрос пользователю.
3. Что входит в План 2 (из спецификации): пилюля с анимациями (§4.2, §5.4), окно настроек с разделами (§4.3), онбординг (§4.4), история, счётчики использования, светлая тема и переключатель темы, звуки старта/стопа, i18n RU/EN, автозапуск, автообновление (tauri-plugin-updater), иконка в трее с состояниями. Подключить дизайн-скилы пользователя: `emil-design-eng`, `apple-design`, `high-end-visual-design` (и др. по ситуации). Иконку/бренд — отдельно через `brandkit`.
4. Добавь в План 2 задачи из «Долгов» ниже, которые касаются UI (M2, M6, M8, M11 и проверки из «Не проверено»).
5. Исполнение — как в Плане 1: пользователь выбрал **Native** (`executing-plans`), ветка `feat/<имя>`, коммит + `git push` после каждой задачи, в конце — свежий ревьюер на самой сильной модели, затем `finishing-a-development-branch`.

## Долги из финального ревью Плана 1 (отложенные мелочи)

- M1 Вставка блокирует цикл оркестратора до 500 мс, пока зажат модификатор.
- M2 После таймаута назначения клавиши (15 с) захват остаётся активным и «съедает» следующее нажатие горячей клавиши.
- M4 Запасной «умный пробел» может добавить пробел в пустое поле Slack/VS Code/Терминала; пробелы между предложениями на CJK.
- M5 Потеря микрофона посреди записи без уведомления, если переоткрыть не удалось.
- M6 `HideOverlay` прячет пилюлю, пока ещё идёт обработка.
- M7 Счётчик считает один запрос Gemini и как распознавание, и как LLM.
- M8 Пилюля — обычное NSWindow с уровнем, а не non-activating NSPanel (`tauri-nspanel`), как в плане.
- M9 Caps Lock как горячая клавиша переключает настоящий Caps Lock.
- M10 В режиме «Нажатие» может проглотиться клавиша, пока горячая ещё физически зажата.
- M11 Горячей клавишей можно назначить букву.
- M12 Блокирующая работа в async-потоках (чтение Keychain на каждое нажатие, старт/стоп микрофона, буфер 10 мин в f32).
- M13 Записи длиннее ~8 мин могут превысить лимит inline-аудио Gemini (20 МБ).
- M14 Event tap не выключается/не инвалидируется при остановке.
- M15 `"csp": null` в `tauri.conf.json`.
- M16 Расхождения доков: спецификация §6.2 говорит listen-only tap, §6.5 — `gemini-3.5-flash` вместо flash-lite.
- M17 «Повторить» идёт через общую очередь, а не «сразу».

## Не проверено вживую (перенести в QA Плана 2)

Сон → пробуждение → диктовка; 100 диктовок подряд; 20 нажатий короче 0,3 с; отключение наушников во время записи; бюджеты «нажатие → пилюля < 50 мс» и «нажатие → первый сэмпл < 100 мс»; автотест вставки на русской раскладке. Память: основной процесс 33 МБ, процессы WebKit не посчитаны (в Плане 2 — создавать окно настроек лениво).

## Идеи на будущее (roadmap)

- Потоковое распознавание во время речи (`gemini-3.5-transcribe-live`), чтобы от отпускания клавиши до текста было < 1 с.
- Сжатие аудио перед отправкой (FLAC/Opus) — меньше трафика на медленных сетях.
