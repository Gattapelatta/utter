## Первым делом: открытый баг (пользователь ждёт)

**«После успешной вставки окно само резко пропадает»** — остров должен плавно втянуться в чёлку (§5.4: 0,6 с `cubic-bezier(0.4,0,0.2,1)`, окно `orderOut` через 800 мс), а пропадает мгновенно. Уже сделано и **не помогло**: tween вместо пружины + задержка скрытия 800 мс; плавное гашение содержимого 0,5 с. Проверено и **не причина**: `hidesOnDeactivate` (выставлен `false`, класс панели его не переопределяет).

Не гадай — измерь (я трижды ошибся вслепую):
1. Добавь инструментирование: в Rust — лог при получении `Hidden` и при фактическом `orderOut` (с поколением `HideGate`); на странице — при переходе в hidden снимать `getBoundingClientRect()` острова каждые 100 мс 0…900 мс и слать в лог командой (по образцу `overlay_frames`). Один прогон диктовки у пользователя → по логу видно: идёт ли анимация выхода в WKWebView и не убирается ли окно раньше.
2. Подозреваемые: анимация выхода `AnimatePresence` не запускается в WKWebView (сразу размонтирование); окно убирается раньше (лишний `Hidden`/`orderOut` после доставки, `set_position`/`orderFront` на `Done`); `transitionEnd: transform none` ломает выход из `none`.
3. Попроси пользователя (по желанию) выдать Claude «Запись экрана» в Системных настройках — тогда `screencapture` покажет окна и можно снимать кадры самому.

Остальное по пилюле пользователь принял: размер/позиция Капли (вариант C: 48×50, центр пары на 61 pt), дуги вместо колец (±30°, не заходят под вырез), тучки в левом «крыле», плавность кадров (лог: ровно 60 к/с).

## Решения, принятые по ходу (сверх спецификации)

1. Провайдер по умолчанию — Google Gemini, один запрос «аудио → готовый текст» на `gemini-3.5-flash-lite` (`thinking_level: minimal`). Бесплатный суточный лимит Gemini Google больше не публикует — полоски лимита для Gemini нет, пока пользователь не пришлёт RPD из aistudio.google.com/rate-limit (просили, ответа ещё нет).
2. Активный перехват клавиатуры; свои нажатия помечены `SYNTHETIC_MARK`.
3. **M14 исправлен 2026-10-08:** при перезапуске перехвата (каждое пробуждение, ночью их ~60 из-за Power Nap) старый tap теперь выключается и инвалидируется — раньше «брошенные» перехваты копились и клавиатура вставала. Проверено `CGGetEventTapList`.
4. Пилюля «Капля» из чёлки — см. §4.2 и эталон `docs/design/drop-prototype.html`. Звуков нет. Таймер — Manrope 600.
5. Длинные записи режутся на паузах по ходу речи (≥ 7 с, пауза ≥ 0,3 с, принудительно на 15 с), хвост > 9 с делится пополам и обрабатывается параллельно (§3.4a). Живой замер после этого ещё не сделан — попроси пользователя надиктовать 30–60 с и посмотри `piece sent while speaking` / `total_ms`.
6. В лог пишутся причины ошибок провайдера (`job failed`, `http error`) — однажды запросы «висели» по 10 с без видимой причины, после перезапуска прошло.
